# Short GPU 3x3 median selection

Date: 2026-10-15. Parent: `3a656a01ca2ade9ae7fd31244f9bb12803131b1d` (merged PR 205).

## Change and boundary

The resident 3x3 median uses 19 generated compare-exchange pairs instead of the
previous pruned padded-bitonic network's 63. Nine byte vectors are sorted in
three triples. Two comparisons select the largest of their minima, three select
the middle of their medians, and two select the smallest of their maxima.
Three final comparisons select the median of those three candidates. Each pair
uses lane-wise integer min/max, preserving all four physical components exactly.
This is a reduction in generated pairs, not a machine-instruction count claim.
Unused padded declarations in the shared shader generator are unchanged and do
not participate in the new network.

For any threshold, each sorted triple has 0..3 values at or above it. Majority
among (any triple has three, at least two triples have two, all triples have one)
is equivalent to at least five values among all nine. Thresholding commutes with
min/max, so this selection yields the median for arbitrary byte values and ties.
Exhaustive binary patterns, all distinct rank permutations and independent byte
sorting test this property.

The 5x5 network and complete generated shader string remain identical. The
shared shader generator, sampling, replicate/constant-zero borders, workgroup
size, dispatch, planner, runtime validation, lazy pipeline family, API body,
receipts, metadata and ownership are unchanged. There is one device pass, four
physical output bytes per pixel and no image-sized scratch or new resource.
No upload/readback/wait, dependency, unsafe code, automatic placement decision
or CPU behavior is added. All 1..=4 logical channels, including alpha, remain
independent. First pipeline compilation stays lazy; measurements below time
warmed calls rather than cold compilation.

## Correctness and integration

The new pure test covers all **362,880** permutations of ranks 0..8 against
both the old network and the independent expected rank 4. The existing test
covers all **512** binary 3x3 inputs, **200,000** seeded byte windows across
3x3/5x5 and **512** constant windows against independent sorting. The pure test
also compares every 5x5 pair and the full generated WGSL string to the frozen
implementation.

A frozen complete PR 205 median implementation builds independent old pipelines.
Its public-call body changes only the function name/signature and the location
of the same OnceLock lookup, held by the test instead of the runtime. Native
comparisons cover small images, vertical/horizontal strips, odd 1025x257 inputs,
1..=4 channels, random/hot/checker/impulse fixtures, both borders and both kernel
sizes. They compare exact downloaded images, metadata and receipts. Existing
CPU-oracle, strided ROI, padding, live output, input destruction, invalid-limit/
wrong-runtime and concurrent cold-cache tests run unchanged.

All **107** selected native image regression tests passed. The final release
executable also reran the **7** median tests after finalizing the measurement
fixture. The frozen GPU comparison checks **384** calls / **50,218,560**
logical bytes; existing CPU-image comparisons check **896** calls /
**5,248,880** logical bytes, with physical unused lanes checked separately.
These count comparisons, not distinct pixels. All **4** public facade tests
(median, bilateral and two transfers), all-feature/all-target Clippy with
warnings denied, CPU-only/WASM facade checks, formatting and diff checks passed.

Source verification allows only the early 3x3 network branch, explanatory
comments and native test-module declarations to change in pre-existing GPU
sources. It compares the complete frozen implementation against PR 205 with
explicit test visibility/cache-location substitutions. The shared generator,
planner and public call body remain identical; **335** other pre-existing
sources, including all **97** WGSL source files, remain unchanged. The 3x3
shader generated by Rust is intentionally different. Manifests hash **342**
GPU source/WGSL, public median smoke-test and executable files before/after
surveys. Tracked/nonignored files and the PR body have zero forbidden local
adapter-name matches.

## Isolated measurements

Two sequential surveys follow all builds/tests and a 15-second quiet window.
Process census covers native build/test/benchmark executables and foreign Python
processes (excluding the owned measurement driver and identified idle HTTP
servers). It rejects an entire attempt if another build/test/benchmark overlaps;
only the owned child may be cancelled. Accepted runs require one passing test,
no overlap and empty stderr. Statistical analysis starts after both runs and
verification of exact source/executable hashes.

Eleven fixtures use three warm cycles and 30 paired samples per route, with
alternating old/new order. `resident` includes the complete API call and
`wait_idle` with an existing uploaded input and owned output. Readback, byte/
receipt assertions and output recycling follow outside its timer. `full`
includes upload, API call, readback and GPU-image recycling; byte equality is
asserted after its timer. Both routes compare each result to the current CPU
median. Runtime/fixture creation, CPU reference preparation and cold pipeline
compilation are excluded. Thus resident timings include host dispatch/wait
costs; neither API route is a GPU timestamp-only measurement.

A third `pass` route records GPU pass-boundary timestamps for the exact old/new
generated shader strings, with equivalent inferred layouts and the same uniform,
source, output format and dispatch. Pipelines, bindings and two owned outputs
are prepared before timing. Both passes share one command buffer per paired
round with alternating order. Explicit collection reads 32 query bytes per
round; query collection/setup/readback and CPU work are outside the timestamps.
Both output images are checked against CPU after the rounds. This test-only
fixture separates GPU compute from host/transfer costs without changing the
production API. Its times must not be called frame/API latency. The benchmark
runtime explicitly enables timestamp queries; public API routes do not record
queries.

Profiles: 0 varied bytes, 2 constant 255, 4 impulses on 17. Borders: 0 replicate,
1 constant zero. Cases include 65x33 through 1920x1080, a 4097x17 strip, odd
1025x257, and two 5x5 controls with identical shaders. All channel counts and
borders receive correctness coverage; timed channel counts are 1/3/4.

Environment: native Windows x86_64, rustc 1.98.1 (`48a229cea`, 2026-09-01),
Vulkan discrete-device backend and 12 available CPU workers. Runtime image pool
budget is 67,108,864 bytes (64 MiB), also recorded in each raw environment
row. GPU model names are omitted.
Local latency is not a portable throughput guarantee.

Ratios are geometric means of paired old/new sample ratios; above one favors
the new route. Percentile 95% intervals resample paired log ratios 10,000 times,
seed `2026101507 + 100*survey + 10*case + JSON_field_index`, sorted bounds
249/9749. Intervals crossing one are inconclusive. All adverse/inconclusive
results are retained; zero samples suppress ratios.

The initial two native-only-census surveys were discarded after a process
audit identified concurrent foreign Python tests/benchmark drivers. The census
was expanded before repeating either survey. Their 44 comparison rows, raw
logs, source/executable hashes and process-audit receipt are preserved at
`C:/Users/rsasa/Workspace/SpatialRust/target/automation/median-nine-overlap-audit1`.
They are not used to assess this change's speed. Discarding them follows the
pre-existing no-overlap requirement, including their favorable and adverse rows.

After the host became quiet, both final surveys were accepted on attempt 2,
with no overlapping work and empty stderr (13.10 and 12.55 seconds of test
execution). Source/executable hashes match before and after. The 66 comparisons
have 30 nonzero paired samples each: **31** favorable intervals, **35** crossing
one and **zero** wholly adverse intervals. Some individual medians are worse;
all rows are retained below.

For varied 1024x1024 grayscale 3x3 inputs:

- GPU `pass` medians: 0.195888 → 0.129824 ms and 0.195680 → 0.129776 ms
  (33.7% lower in both surveys). Paired ratios are 1.505098
  [1.500890, 1.509155] and 1.503260 [1.499059, 1.507366].
- `resident` API medians: 0.588900 → 0.513950 ms and 0.510100 → 0.450750 ms
  (12.7% and 11.6% lower). Ratios are 1.129333 [1.085996, 1.171553] and
  1.128472 [1.030726, 1.226403].
- Transfer-inclusive `full` medians: 5.359750 → 5.232300 ms and
  5.205000 → 5.291950 ms. Both intervals cross one, so no completed full-call
  speedup is established for this case.

For varied 1920x1080 RGB, GPU pass medians fall 0.706992 → 0.539248 ms and
0.700240 → 0.539136 ms (23.7% and 23.0% lower), while resident API medians
fall 0.811800 → 0.674000 ms and 0.841450 → 0.689250 ms (17.0% and 18.1%
lower). Its full-call intervals also cross one in both surveys.

All **18** 3x3 GPU-pass comparisons favor the new network. The **4** 5x5
GPU-pass controls cross one, consistent with identical generated shaders.
Resident API comparisons have 12 favorable and 10 inconclusive intervals;
a favorable 5x5 control in only survey 1 must not be attributed to the 3x3
algorithm. Full calls have only one favorable interval and 21 inconclusive
intervals; that one full-call condition is not favorable in the other survey.
Thus there is repeatable GPU-stage improvement and selected resident-API
improvement, without a general transfer-inclusive speed claim. GPU timestamps
must not be substituted for application latency. Absolute API timings vary
with host scheduling, input geometry and transfer costs.
