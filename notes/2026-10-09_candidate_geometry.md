# Geometry ambiguity remains after candidate-search acceleration

Run with the installed SpatialRust extension and NumPy:

```bash
LD_LIBRARY_PATH=/workspace/SpatialRust-python-delivery/target/onnxruntime \
 /workspace/.spatialrust-env/comparison-venv/bin/python \
 /workspace/SpatialRust-python-delivery/scripts/study_candidate_geometry.py
```

Artifacts, exact candidates, generating poses, all assessments and source hashes
are saved under `/workspace/SpatialRust-python-delivery/target/candidate-geometry-study/`.
The standalone HTML compares selected candidate, support, RMSE and pose errors.

Twelve conditions use random volumetric clouds (five seeds), random XY planes
(five seeds), a deterministic 180-point ring and the same ring with three
asymmetric protrusion points. Source coordinates are generated by a 20-degree
Z rotation plus translation (12, -8, 5) mm. Each condition supplies identity,
the exact generating inverse pose and that pose followed by a 180-degree Z
rotation. This truth-informed grid diagnoses selection and ambiguity; it does
not demonstrate automatic initial-pose generation or global registration.

Selection is finalized from forward supported count, gated RMSE and stable input
order before generating-pose errors are assessed. Search gate is .15 m, support
gate .05 m, voxel leaf .025 m and iteration limit 100 per stage. Correctness for
this study means rotation error below 1 degree and translation error below .01 m.
Every selected report and each candidate's pose/support/convergence matches
independent file alignment exactly; all 36 optimized candidate runs succeeded.
The full Python regression suite passed 200 tests.

| Geometry | Selected generating pose correct | Incorrect candidates with >=98% forward support |
| --- | --- | --- |
| Random volume | 5/5 | 0 |
| Random XY plane | 5/5 | 0 |
| Symmetric ring | 0/1 | 2 |
| Ring plus three asymmetric points | 1/1 | 2 |

On the symmetric ring, exact and 180-degree-alternative poses both have 100%
forward support and RMSE about 4.591e-8 m. Their difference is only about
1.5e-19 m in the recorded f64 RMSE; the alternative wins this run's strict
ordering and has 180-degree error relative to the generating pose. This is
geometric non-identifiability, not evidence that one physically distinct pose
can be recovered from symmetric XYZ alone. Candidate order resolves exact
ties only, not numerically near-equal scores. Different arithmetic/platforms
could select differently without recovering unique pose information.

Adding three asymmetric points makes the exact pose achieve 183/183 support
while both wrong candidates retain 180/183 (98.36%). The correct candidate is
selected by supported count, even though the 180-degree alternative has slightly
lower gated RMSE after its three unmatched markers are excluded. Thus low gated
RMSE and high support percentages can hide precisely the sparse geometry that
disambiguates pose. Denoising or downsampling those markers could remove useful
information; this study does not run those interventions and does not yet prove
their effects.

The random plane succeeds with this grid; planarity alone is not established as
a failure cause for point-to-point ICP here. Ring fixtures are deterministic
single controls, not five independent seed trials. No noise, partial overlap,
real scans or cross-library comparisons are included. A useful next diagnostic
is disagreement between similarly supported candidate poses, without presenting
that disagreement as a calibrated uncertainty probability.
